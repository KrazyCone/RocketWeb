# RocketWeb

**The official OpenRocket desktop app, running in a browser tab.** No install, no account,
no server-side compute: the unmodified upstream JAR is executed on the visitor's own device
by [CheerpJ](https://cheerpj.com), a WebAssembly JVM that runs the real Swing UI.

Design rockets, run flight simulations with OpenRocket's genuine physics engine and export
the results — then keep the design on your own machine. The hosting side is a handful of
static files, so it fits comfortably on Firebase Hosting's free Spark plan.

> `Main-Class`. A full in-browser boot has **not** been checked by the author (no browser in
> the build environment) — see [Verified](#verified) for exactly what was and was not tested.

## Try it locally (any OS)

Requirements: **Node.js 20+** and a network connection for the first run.

```bash
git clone https://github.com/KrazyCone/RocketWeb.git
cd RocketWeb

npm run fetch     # downloads the latest OpenRocket release -> public/OpenRocket.jar
npm start         # serves public/ on http://localhost:3000 with Range support
```

Open <http://localhost:3000> and wait for the first boot. There is **no `npm install` step**:
every script uses Node built-ins.

> **Do not serve `public/` with `python3 -m http.server`.** CheerpJ fetches the JAR with
> HTTP Range requests; Python's built-in server ignores `Range` and returns `200`, which
> stalls the runtime. `scripts/serve.mjs` and Firebase Hosting both handle ranges correctly.

Variations:

```bash
OPENROCKET_VERSION=23.09 npm run fetch:force   # pin a specific release
PORT=8080 npm start                            # different port
npm run verify                                 # the checks CI runs before deploying
```

## Deploy it on macOS, step by step

All of this happens in **Terminal.app** (zsh). Budget 10–15 minutes, most of it the 83 MB
download. You need a Google account that can create a Firebase project.

### 0. Prerequisites

| Need | Check | Install |
| --- | --- | --- |
| Node.js 20+ | `node -v` | `brew install node` |
| Git | `git --version` | `xcode-select --install` |
| A Firebase project | [console.firebase.google.com](https://console.firebase.google.com) | free Spark plan, no card |

### 1. Install Node.js (skip if `node -v` already prints v20 or newer)

```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
brew install node
node -v && npm -v
```

On Apple Silicon, Homebrew installs into `/opt/homebrew`. If the installer asks you to add
it to your `PATH`, do that once and open a new terminal:

```bash
echo 'eval "$(/opt/homebrew/bin/brew shellenv)"' >> ~/.zprofile
source ~/.zprofile
```

No Homebrew? nvm or the official installer from <https://nodejs.org> both work — any Node
20+ is fine.

### 2. Clone the repo and download the JAR

```bash
git clone https://github.com/KrazyCone/RocketWeb.git
cd RocketWeb
npm run fetch
```

`npm run fetch` resolves the newest official release on
[openrocket/openrocket](https://github.com/openrocket/openrocket/releases), downloads
`public/OpenRocket.jar` and writes `public/openrocket-version.json`. It fails loudly if the
download is not a real JAR.

```bash
ls -lh public/OpenRocket.jar     # expect ~79 MiB (83,149,098 bytes for 24.12)
```

Pin an older release if you prefer: `OPENROCKET_VERSION=23.09 npm run fetch:force`.

### 3. Run it locally before deploying

```bash
npm start
```

Open <http://localhost:3000>. Chrome, Edge or Firefox are the best bets; Safari works but
budgets less memory for the JVM. `Ctrl+C` stops the server.

### 4. Sign in to Firebase

```bash
npm install -g firebase-tools
firebase --version
firebase login
```

`firebase login` opens a browser window — approve it with the account that owns (or will own)
the Firebase project, then come back to the terminal.

Getting `EACCES`/permission errors from the global install? Either fix npm's prefix ownership
once:

```bash
sudo chown -R "$(whoami)" "$(npm config get prefix)/lib/node_modules"
```

or skip the global install entirely and prefix each command with `npx`:

```bash
npx firebase-tools login
```

### 5. Create or select the Firebase project

If the project already exists in the console:

```bash
firebase projects:list      # copy the exact project ID (not the display name)
firebase use --add          # choose it, give it the alias "default"
```

If you do not have a project yet, create it from the CLI. The lowercase ID has to be globally
unique — if it is taken, pick another (`rocketweb-<initials>`, say):

```bash
firebase projects:create rocketweb --display-name "RocketWeb"
firebase use rocketweb
```

`.firebaserc` ships with the placeholder ID `rocket-on-web`; `firebase use` and
`firebase use --add` rewrite it to your real project ID. **You do not need `firebase init`** —
`firebase.json` is already the hosting config this site wants.

### 6. Deploy

```bash
npm run verify                                  # optional pre-flight checks
npx firebase-tools deploy --only hosting
```

The CLI ends with:

```
Hosting URL: https://<your-project-id>.web.app
```

That URL is public and works on any device, including your iPhone. Load it once on the Mac
and once on the phone to confirm the JVM starts on both.

To redeploy after editing anything in `public/`:

```bash
npx firebase-tools deploy --only hosting
```

> **Re-run `npm run fetch` if `public/OpenRocket.jar` is missing.** A `firebase deploy`
> without the JAR publishes a page that cannot boot — that is the single most common mistake.
> `npm run deploy` (once `firebase-tools` is installed globally) does fetch + deploy together.

### 7. Optional: deploy automatically on every push

The workflow in `.github/workflows/deploy.yml` fetches the latest JAR, verifies it, and
deploys on every push to `main` (and on **Actions → Deploy to Firebase Hosting → Run
workflow**, where you may pin an OpenRocket version). All it needs is one secret.

1. Open the [Google Cloud console](https://console.cloud.google.com/iam-admin/serviceaccounts)
   with your Firebase project selected.
2. **IAM & Admin → Service Accounts → Create service account**, e.g. `github-hosting`.
3. Grant it the role **Firebase Hosting Admin**.
4. Open the account → **Keys → Add key → Create new key → JSON** and download the file.
5. Register the file as a repo secret (it is a long-lived credential — never commit it):

   ```bash
   brew install gh        # if you do not have the GitHub CLI
   gh auth login
   gh secret set FIREBASE_SERVICE_ACCOUNT < ~/Downloads/github-hosting-*.json
   ```

6. Optionally pin the project ID as a repository variable (it defaults to `rocket-on-web`):

   ```bash
   gh variable set FIREBASE_PROJECT_ID --body "your-project-id"
   ```

7. Push to `main` and watch the run under **Actions**:

   ```bash
   git push origin main
   ```

`GITHUB_TOKEN` is supplied by Actions automatically and only raises GitHub API rate limits
while resolving the latest release.

### 8. Optional: custom domain

In the Firebase console: **Hosting → Add custom domain**, then point the DNS records it
shows at Firebase. Caching headers from `firebase.json` apply to custom domains too, and
Firebase issues the TLS certificate for free.

## How it works

```
Visitor's browser
├── public/index.html              wrapper UI (toolbar, progress, footer, ad slot)
│   ├── public/app.js              boot sequence + file bridge
│   ├── public/runtime-config.js   Java version, JAR path
│   └── cjrtnc.leaningtech.com/4.3/loader.js   CheerpJ (Java 17 in WebAssembly)
│
├── GET /OpenRocket.jar            official release asset, fetched by script/CI
│
└── cheerpjInit({ version: 17 })
    cheerpjCreateDisplay(-1, -1, #display)      fills the viewport, follows resizes
    cheerpjRunJar("/app/OpenRocket.jar")        the real OpenRocket Swing UI
```

- **Zero backend.** Firebase serves static bytes only; all computation happens locally.
- **No re-implementation.** OpenRocket's aerodynamics and flight simulation are used exactly
  as shipped upstream — this repo contains no Java source.
- **Lightweight repo.** The JAR is downloaded by `scripts/fetch-openrocket.mjs` locally and
  in CI, and never committed.

### CheerpJ and Java compatibility (read before changing versions)

CheerpJ 3.0 supports **Java 8 only**. Modern OpenRocket releases target newer Java, so
"CheerpJ 3.0 + latest OpenRocket" cannot work: the JVM throws
`UnsupportedClassVersionError` before any window appears.

| CheerpJ build | Loader `<script>` | Java runtimes | Runs OpenRocket |
| --- | --- | --- | --- |
| 3.0 / 3.1 | `https://cjrtnc.leaningtech.com/3.0/cj3loader.js` | 8 | 15.03 and older only |
| 4.0 | `https://cjrtnc.leaningtech.com/4.0/loader.js` | 8, 11 | 22.02 / 23.09 |
| **4.3** (used here) | `https://cjrtnc.leaningtech.com/4.3/loader.js` | 8, 11, 17 | **24.12 ✓** |
| 5.0 | `https://cjrtnc.leaningtech.com/5.0/loader.js` | 8, 11, 17, 21 | newer releases |

OpenRocket moved to **Java 17 in 24.12**, the current release, so this repo loads CheerpJ
**4.3** and calls `cheerpjInit({ version: 17 })`. If you deliberately want the 3.0
`cj3loader.js` URL, pin a Java 8 OpenRocket release as well:

```html
<!-- public/index.html -->
<script src="https://cjrtnc.leaningtech.com/3.0/cj3loader.js"></script>
```

```bash
OPENROCKET_VERSION=15.03 node scripts/fetch-openrocket.mjs --force
# then set javaVersion: 8 in public/runtime-config.js
```

Everything else in the wrapper — full-viewport display, progress, file transfer — is
version-independent.

## Using files (`.ork` designs, simulation CSVs)

OpenRocket runs against a virtual filesystem; the wrapper makes it practical:

| Mount | Direction | Contents |
| --- | --- | --- |
| `/app/` | read-only | this site's files, i.e. `/app/OpenRocket.jar` |
| `/str/` | JS → Java | designs picked with **Open .ork…** on the toolbar |
| `/files/` | read/write (Java) | persistent storage in the browser (IndexedDB) |
| `/files/downloads/` | Java → device | files saved here download automatically (CheerpJ 4.3+) |
| `/files/uploads/` | title-bar upload button → Java | not persistent across browser restarts |

**Import.** The simplest path is the upload arrow CheerpJ draws in the OpenRocket window's
title bar, followed by *File → Open* inside the app. The toolbar's **Open .ork…** button is
the alternative: it stages the file at `/str/<filename>`, which you open with *File → Open…*
by typing that path.

**Export.** In OpenRocket use *File → Save As…* (or *Export* for simulation CSVs) and target
`/files/downloads/`; CheerpJ hands the file to the browser's download manager. Anything saved
elsewhere under `/files/` can be retrieved with **Save to device…** on the toolbar, which
reads it back with `cjFileBlob()` and downloads it.

**Persistence.** Files under `/files/` survive reloads in the same browser profile on the
same origin. Nothing is synced anywhere: no account, no server, nothing leaves the device.

## Configuration

`public/runtime-config.js`:

| Key | Default | Meaning |
| --- | --- | --- |
| `javaVersion` | `17` | passed to `cheerpjInit({ version })`; must satisfy the JAR's bytecode |
| `jarPath` | `/app/OpenRocket.jar` | CheerPJ path of the application JAR |
| `versionManifest` | `openrocket-version.json` | build metadata used for the version badge |
| `displayElementId` | `display` | element that `cheerpjCreateDisplay()` fills |

The CheerpJ build is chosen by the `<script>` tag in `public/index.html` (see the
compatibility table). The JAR release is chosen by `OPENROCKET_VERSION` at build time, or by
the `openrocket_version` input when running the workflow manually.

## Free-tier reality check for an 83 MB application

Firebase Hosting's Spark plan includes **10 GB of storage** and, per the pricing table,
**360 MB/day of data transfer** (the quotas page phrases the same allowance as 10 GB/month).
Fine for a small page — but not for many cold starts of an 83 MB JAR:

- roughly **4 uncached loads per day** exhaust the daily allowance;
- repeat visits are cheap, because `firebase.json` caches the JAR for 7 days
  (`max-age=604800`) and the CheerpJ runtime comes from CheerpJ's CDN, not your quota;
- past the allowance Firebase gives a short grace period, then disables the site until the
  next month.

Options, in order of effort:

1. **Accept it for a personal/demo site** — a handful of visitors a day fits in Spark.
2. **Shrink the payload** by pinning a smaller release (`OPENROCKET_VERSION=23.09` via the
   workflow input).
3. **Put a free CDN in front** (for example Cloudflare in front of `*.web.app`) so repeat JAR
   requests are served from the edge.
4. **Move to Blaze** with a budget alert if you expect real traffic. That costs money.

The wrapper page itself is a few KB and stays far inside the free limits either way.

## Known limitations

These come from running a desktop Swing application inside a WebAssembly sandbox:

- **3D visualisation is unavailable.** OpenRocket's 3D view uses OpenGL through JOGL native
  libraries, which cannot load in the browser sandbox. The 2D rocket view, component editing
  and the simulation engine are unaffected.
- **No native OS integration** — printing, file associations, drag-and-drop from the desktop.
  Use the virtual filesystem and the download bridge instead.
- **Slower and memory-hungry.** The JVM runs inside WebAssembly; heavy simulations and long
  motor databases take noticeably longer than on a desktop JVM. Several GB of free RAM help.
- **Touch devices** get long-press-as-hover emulation (CheerpJ 4.3): workable on an iPhone,
  but an AWT/Swing desktop UI is never going to feel like a native mobile app.
- **CheerpJ licence gate.** The unlicensed (Community) runtime shows its non-commercial
  licence notice on screen. Commercial use needs a CheerpJ licence from Leaning Technologies.

## Troubleshooting

| Symptom | Cause / fix |
| --- | --- |
| `zsh: command not found: npm` on a new Mac | Homebrew is not on `PATH` — `eval "$(/opt/homebrew/bin/brew shellenv)"`, then open a new terminal. |
| `firebase: command not found` | `npm install -g firebase-tools`, or use `npx firebase-tools …`. |
| `EACCES` on `npm install -g` | `sudo chown -R "$(whoami)" "$(npm config get prefix)/lib/node_modules"`. |
| Deploy succeeds, page shows nothing | `public/OpenRocket.jar` was missing at deploy time — run `npm run fetch` and deploy again. |
| Blank stage, console mentions a failed fetch | Host does not answer HTTP Range requests (e.g. `python3 -m http.server`); use `npm start` or Firebase Hosting. |
| `UnsupportedClassVersionError` | Java version mismatch — see the compatibility table and align `javaVersion` with the pinned JAR. |
| Hangs on "Starting the Java runtime" | `cjrtnc.leaningtech.com` blocked (corporate proxy, content blocker, offline). |
| "This browser ran out of memory" | Close other tabs; 83 MB of JAR plus the JVM need real RAM. |
| Files saved in OpenRocket are not found | Save into `/files/downloads/`, or type the exact path into **Save to device…**. |
| `firebase login` cannot reach the browser | Re-run it with `--no-localhost` and paste the code it prints. |
| Site disabled | Spark data-transfer allowance exhausted for the month; see the free-tier section. |

## Verified

Checked while building this repo (24 November 2026):

- **Release resolution works without credentials.** `scripts/fetch-openrocket.mjs` resolved
  `release-24.12` through the `releases/latest` redirect (the unauthenticated GitHub API was
  rate-limited) and downloaded `OpenRocket-24.12.jar`, 83,149,098 bytes,
  sha256 `4959b72f52f5f607941e9722abbb7b7f0c4a38ebbbf84204a329db9f31c4f897`.
- **The JAR is runnable as `java -jar`.** Its manifest declares
  `Main-Class: info.openrocket.swing.startup.OpenRocket`, which is what `cheerpjRunJar()`
  needs.
- **Java 17 is the right runtime.** The main class's bytecode is major version **61**
  (Java 17), confirming `javaVersion: 17` and that CheerpJ 3.0 (Java 8) would fail.
- **The CheerpJ CDN serves the loader.** `https://cjrtnc.leaningtech.com/4.3/loader.js`
  answers `200` `text/javascript`.
- **The static layer behaves like Firebase Hosting.** With `scripts/serve.mjs`: `/` → `200`
  `text/html`, `/app.js` → `200` `text/javascript`, and `/OpenRocket.jar` with
  `Range: bytes=100-199` → `206` with `content-range: bytes 100-199/83149098`.
- **Configs parse.** `firebase.json`, `.firebaserc`, `package.json`,
  `public/openrocket-version.json` and `.github/workflows/deploy.yml` are all valid.
- **JavaScript syntax-checks.** `node --check` passes on `public/app.js` and every script.

**Not verified:** an actual in-browser boot and render, a live Firebase deployment, and the
`/str/` import path. The build environment had no browser with network access, so the first
real page load (JVM start → OpenRocket window → a simulation run) remains to be done; the 3D
view is expected to be unavailable as described above.
